# Introduction 
This is the go deploy infrastructure as code repository using Terraform to deploy cloud and on premise infrastructure.

This contains the shared modules to be uterlised by other repositories to deploy the required infrastructure.
It will also have in template collections

# Getting Started
To install please follow the Terraform guide: [Terraform Installation](https://learn.hashicorp.com/tutorials/terraform/install-cli)

There is also a learning path within this link to learn more about terraform.

# Build and Test
To Build and Test you can run these commands in order:
1. `az login` - This will log you into the Azure CLI
2. `az account set --subscription="SUBSCRIPTION_ID"` - This will set the Subscription to use
1. `terraform fmt -recursive` - This will format the code
2. `terraform init` - This will install all required Modules and Providers
3. `terraform validate` - This will check that your files and dependencies are correct
4. `terraform plan` - This will show you the added, changed and destoryed resource, plus if it will have any conficts.
5. `terraform apply` - This will apply the changes to the destination environment.

To test the modules within the repository there is a `testing` folder or you can create a folder called `testing`
It has been excluded within the gitignore, so any new changes will not be pushed up to make it safe to use.

### Recommended
- Any environment specific details like Subscription ID you can pass in by creating a `variables.tfvars` file in a destination out of the repository. Then when runnning the `plan` and `apply` pass in the vars file e.g. `terraform plan --var-file="../variables.tfvars`
- Once you are finished with the environment remeber to destory it with `terraform destory`

### Deployments
- For the CI Build please remeber to add all new modules to the `azurepipeline.yml`

# Code Quality
To maintain readbility and code quality we ask that you follow the guide as below.

Before committing your code, please run the Terraform Format command on all folders with changes. This will format all the code as required.
Command: `terraform fmt -recursive`

### Variables
- All Variables should start with their resource type and then the parameter e.g. Resource Group Name = `resource_group_name`.
- All Variables should be places in a `variables.tf` file.
- **Variable Types**
    - Standard Variables
        - All Variables are to be lowercase and snakecase.
        - Can be used in all areas
    - Azure DevOps Libary
        - Variable should be uppercase and snakecase.
        - Should only happen in the templates directory `\templates\`.
        - Should be used for environmental variables generated by the Infrastructure Pipeline. These are static values that are the same for each application. For example the environmental name for the ACR that other templates will need access to.
    - Azure DevOps Pipeline
        - All Variables are to be lowercase and snakecase.
        - Should only happen in the resources tfvars files `\pipelines\resource-vars`.
        - Should be formatted `#{VariableName}#` e.g. `#{SubscriptionId}#`
        - Should be used for environmental variables generated by the Code Pipeline. These are no static values that can be different for each application. For example the application name.

### Resources
- All Resource names will be lowercase and snakecase.
- All Resources should be places in a `main.tf` file.
- All Providers used should have a fixed version number.

### Outputs
- All Outputs are to be lowercase and snakecase.
- All Outputs should start with their resource type and then the parameter e.g. Resource Group Name = `resource_group_name`.
- All Outputs should be places in a `outputs.tf` file.

### Modules
- When creating a reference to a module, then name should be lowercase with dashes e.g. `sql-server`.
- Modules should be put in their own folder, named after the module.

### Folder Structure
- Modules belong in their respective environment folder name either `az`, `aws`, `gcp` or `onprem`.
- Templates belong in the `templates` folder.

# Run Import Pipeline
if a resource is not in the state file and you would like to import it you can use the Terraform Import pipeline.
This will configure and import the resource, which below is the information your will need to gather to run this pipeline.

|Field Name | Description | Example |
|---|---|---|
|Terraform Files Location| Location of the root main.tf file | `$(Build.SourcesDirectory)/templates/gd-api-shared` |
|Project Name:| Friendly name of the run | `Import Key Vault Secret`
|Remote Terraform State File Path | name/location of the state file | `sharedapi/terraform.tfstate`
| CSV of Terraform TFVars files paths | CSV of the full TFvars files used in the orginal call | `"$(Build.SourcesDirectory)\pipelines\resource-vars\shared-resource-vars.tfvars","$(Build.SourcesDirectory)\pipelines\resource-vars\base-resource-vars.tfvars"`
|Terraform Resource Name| The Terraform resource that is creating | **Resource Only**: `azurerm_key_vault_secret.secret` <hr/> **Module to Resource:** `module.access-key-secret.azurerm_key_vault_secret.secret`
|Resource ID from Provider| The full ID of what the provider is creating from the provider | `"https://gd-portal-uks-k-vault-03.vault.azure.net/secrets/azResources-storage-primary-access-key/93fb84ad24714a89a85a3cc12f0d03bb"`
